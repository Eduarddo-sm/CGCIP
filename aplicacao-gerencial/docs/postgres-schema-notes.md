# Schema PostgreSQL Proposto

Arquivo SQL:

```text
docs/postgres-schema.sql
```

## Decisao Principal

Usar um unico banco PostgreSQL com dois schemas:

```text
projeto_negocial
├── gerencial
└── negocial
```

Motivos:

- Evita conflito entre tabelas com mesmo nome, como `users` e `sessions`.
- Permite manter separacao logica entre as duas aplicacoes.
- Permite criar relacionamento real entre gerencial e negocial.
- Facilita backup unico.
- Facilita migracao gradual.

## Relacionamento Entre Sistemas

No SQLite, o relacionamento entre as aplicacoes e apenas logico:

```text
gerencial.negociadores.negocial_user_id
gerencial.negociadores.negocial_username
```

No PostgreSQL proposto, esse relacionamento vira FK real:

```text
gerencial.negociadores.negocial_user_id -> negocial.users.id
```

## Conversoes Importantes

### Booleanos

SQLite usa `INTEGER` para campos como `active`.

PostgreSQL usara `BOOLEAN`.

Conversao:

```text
1 -> TRUE
0 -> FALSE
```

### JSON

SQLite armazena JSON como `TEXT`.

PostgreSQL usara `JSONB` para:

```text
gerencial.snapshots.content_json
gerencial.events.delta_json
gerencial.events.metadata_json
```

### Datas

No gerencial, varias datas estao como `TEXT`.

PostgreSQL usara:

```text
TIMESTAMPTZ
```

para campos com data/hora, e:

```text
DATE
```

para campos que representam somente uma data.

### Numericos

Metas e valores financeiros usam `NUMERIC`, nao `FLOAT`.

Exemplos:

```text
meta_pagamento NUMERIC(12, 2)
valor_total_acordo NUMERIC(14, 2)
valor_ho NUMERIC(14, 2)
percentual_ho NUMERIC(7, 2)
```

## Pontos de Normalizacao Antes da Carga

### Carteiras

Valores aceitos:

```text
GAMMA
ALPHA
BETA
```

Exemplo de correcao necessaria:

```text
Alpha -> ALPHA
```

### Roles

O schema aceita temporariamente:

```text
ADMIN
USER
admin
user
```

Isso evita quebrar a carga inicial. Depois podemos padronizar tudo.

### Sessoes

As tabelas `sessions` foram criadas, mas a recomendacao e nao migrar sessoes antigas.

Na virada para PostgreSQL, o mais seguro e obrigar todos os usuarios a fazer login novamente.

## Observacao Sobre Compatibilidade do Codigo

Este passo cria o schema alvo.

Ainda sera necessario adaptar o codigo para PostgreSQL, principalmente no gerencial, porque ele hoje usa SQL SQLite puro com:

```text
?
AUTOINCREMENT
active = 1
lastrowid
```

No PostgreSQL isso precisara virar:

```text
%s ou parametros da biblioteca escolhida
GENERATED BY DEFAULT AS IDENTITY
active = TRUE
RETURNING id
```

No negocial o caminho e mais simples porque ja usa SQLAlchemy.
